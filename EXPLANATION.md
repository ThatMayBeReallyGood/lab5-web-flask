# Лабораторная работа №3: Разработка веб-приложения на Python

## 1. Общая карта проекта

Приложение загружает изображение через multipart-форму, принимает период и тип функции, проверяет данные, применяет к RGB-массиву периодический множитель и строит PNG-гистограммы исходного и нового изображений. Результат собирает Jinja2-шаблон и отображает в HTML-таблицах.

Схема: пользователь → HTML-форма → Flask `POST /` → Pillow → NumPy → matplotlib → base64 → Jinja2.

Структура:

- `app.py`: маршрутизация, валидация, обработка и построение графиков.
- `templates/index.html`: пользовательский интерфейс.
- `static/style.css`: внешний вид.
- `tests/test_site.py`: четыре автоматических теста.
- `requirements.txt`: точные зависимости.
- `.github/workflows/ci.yml`: CI в GitHub Actions.
- `render.yaml`/`Procfile`: конфигурация PaaS и Gunicorn.
- `README.md`: команды запуска и деплоя.

## 2. Используемые технологии

**Flask** реализует WSGI-веб-приложение. Декоратор `@app.route` связывает URL и Python-функцию. **Jinja2** подставляет данные в HTML. **Pillow** открывает и преобразует форматы изображений. **NumPy** выполняет векторные операции над массивом пикселей. **matplotlib** строит гистограммы. **pytest** проверяет функции без ручного просмотра. **Gunicorn** запускает WSGI-приложение на сервере. **GitHub Actions** устанавливает окружение и тесты при push. **Render** предоставляет PaaS-хостинг. **reCAPTCHA** проверяет поведение посетителя на стороне Google.

## 3. Поблоковый разбор

### Блок 1. Инициализация Flask и константы

**Фрагмент кода:**

```python
app = Flask(__name__)
app.config["MAX_CONTENT_LENGTH"] = 10 * 1024 * 1024

ALLOWED_EXTENSIONS = {"png", "jpg", "jpeg", "gif", "bmp", "webp"}
RECAPTCHA_SITE_KEY = os.getenv("RECAPTCHA_SITE_KEY", "")
RECAPTCHA_SECRET_KEY = os.getenv("RECAPTCHA_SECRET_KEY", "")
```

**Назначение:** создается экземпляр Flask и задаются ограничения загрузки, форматы файлов и ключи капчи.

`__name__` сообщает Flask имя текущего модуля и позволяет находить папки `templates` и `static`. Ограничение `MAX_CONTENT_LENGTH` — 10 МБ — защищает сервер от чрезмерно большого multipart-тела. Множество расширений используется только как быстрая предварительная проверка: далее Pillow реально читает тип файла. Ключи берутся из переменных окружения, а не хардкодятся в исходниках.

**Подводные камни:** проверка расширения не заменяет проверку содержимого. Ограничение размера применяется ко всему POST-запросу, а не только к файлу.

### Блок 2. Валидация типа файла

**Фрагмент кода:**

```python
def validate_image_file(file) -> str | None:
    if file is None or not file.filename:
        return "Файл изображения не выбран."
    extension = file.filename.rsplit(".", 1)[-1].lower() if "." in file.filename else ""
    if extension not in ALLOWED_EXTENSIONS:
        return "Допустимы только файлы PNG, JPG, JPEG, GIF, BMP или WEBP."
    file.stream.seek(0)
    try:
        with Image.open(file.stream) as image:
            image.verify()
    except (UnidentifiedImageError, OSError):
        return "Файл поврежден или не является изображением."
```

`FileStorage.filename` содержит имя файла. Расширение отделяется от имени методом `rsplit`. Затем PIL читает начало и структуру данных через `Image.open`, а `verify()` проверяет целостность без сохранения изображения в память целиком. После проверки поток перематывается на начало для повторного чтения.

**Данные до и после:** на входе строковое имя и бинарный поток; на выходе строка ошибки или `None`. `None` означает успешную проверку.

### Блок 3. Валидация периода

**Фрагмент кода:**

```python
def validate_period(period_text: str) -> tuple[float | None, str | None]:
    try:
        period = float(period_text)
    except (TypeError, ValueError):
        return None, "Период должен быть числом."
    if not np.isfinite(period) or period < 2 or period > 1000:
        return None, "Период должен находиться в диапазоне от 2 до 1000 пикселей."
    return period, None
```

HTML передает все текстовые поля строками. Поэтому используется `float()`. `np.isfinite()` дополнительно запрещает `NaN` и бесконечность. Ограничение по пикселям предотвращает доминирование слишком маленьких частот и бессмысленные значения.

### Блок 4. Периодическое умножение

**Фрагмент кода:**

```python
rgb = np.asarray(ImageOps.exif_transpose(image).convert("RGB"), dtype=np.float32)
height, width = rgb.shape[:2]
x = np.arange(width, dtype=np.float32)[None, :]
y = np.arange(height, dtype=np.float32)[:, None]
angle = 2 * np.pi * ((x / period) + (y / period))
wave = np.sin(angle) if function_name == "sin" else np.cos(angle)
multiplier = (wave + 1.0) / 2.0
result = np.clip(rgb * multiplier[:, :, None], 0, 255).astype(np.uint8)
```

Сначала EXIF-ориентация преобразуется в реальную ориентацию изображения, после чего получается RGB-массив формы `(height, width, 3)`. Массивы `x` и `y` создают сетку координат: каждая точка имеет один x-индекс и y-индекс.

Аргумент синуса:

$$
\theta(x,y)=2\pi\left(\frac{x}{T}+\frac{y}{T}\right),
$$

где $T$ — период в пикселях. Горизонтальная и вертикальная составляющие присутствуют одновременно. Для cos аналогичный аргумент, а разница с sin определена начальной фазой.

После вычисления $wave \in [-1,1]$ применяется нормировка:

$$
M(x,y)=\frac{wave(x,y)+1}{2}, \quad M\in[0,1].
$$

Тогда исходный канал умножается на множитель. Если исходный пиксел равен 180 и множитель равен 0.5, результат близок к 90. `clip` защищает от выхода за 0–255, а `astype(np.uint8)` приводит к типу цифрового RGB изображения.

**Почему так:** векторные NumPy-операции быстрее поэлементного перебора на Python и упрощенно выражают математику. Формула без нормировки дала бы отрицательные значения, поэтому приведение к `[0,1]` является обязательным вариантом масштабирования.

### Блок 5. Построение гистограмм

**Фрагмент кода:**

```python
rgb = np.asarray(image.convert("RGB"))
fig, ax = plt.subplots(figsize=(7, 3.2), dpi=120)
for channel, color in enumerate(("red", "green", "blue")):
    ax.hist(rgb[:, :, channel].ravel(), bins=256, range=(0, 256),
            color=color, alpha=0.55, label=color.upper())
buffer = io.BytesIO()
fig.savefig(buffer, format="png", bbox_inches="tight")
```

Для каждого канала берутся все пиксели через одномерный массив `.ravel()`. Отрезок `[0,256)` разбивается на 256 интервалов, поэтому нулевые значения попадают в первый столбец, а 255 — в последний. График сохраняется в оперативном буфере без записи временных файлов. Base64 позволяет встроить PNG в атрибут `src` HTML `<img>`.

**Подводный камень:** при нескольких одновременных запросах matplotlib может потреблять память. Вариант Agg и явное `plt.close(fig)` закрывают графики после создания и уменьшают утечку ресурсов.

### Блок 6. Проверка reCAPTCHA

**Фрагмент кода:**

```python
response = requests.post(
    "https://www.google.com/recaptcha/api/siteverify",
    data={"secret": RECAPTCHA_SECRET_KEY, "response": user_response},
    timeout=5,
)
```

Браузер получает виджет и генерирует одноразовый токен. Flask читает токен из поля `g-recaptcha-response`, отправляет секретный ключ и токен на Google. Поле `success` в JSON определяет итог. Секретный ключ никогда не передается шаблону или клиентскому JavaScript.

В режиме разработки отсутствующий секретный ключ пропускает проверку. Это удобно для тестов, но на боевом Render такая конфигурация небезопасна. Поэтому ключи должны быть заданы в переменных окружения PaaS-сервиса.

### Блок 7. Маршрут POST

**Фрагмент кода:**

```python
@app.route("/", methods=["GET", "POST"])
def index():
    if request.method == "POST":
        uploaded_file = request.files.get("image")
        period_text = request.form.get("period", "")
```

Для GET код только отрисовывает форму. Для POST Flask получает файл через `request.files`, а текстовые поля через `request.form`. Проверка выполняется до обработки. Только после успешной валидации исходник открывается, преобразуется и передается шаблону в виде словаря `results`.

**Важно:** имя поля `<input name="image">` должно совпадать с ключом `request.files.get("image")`; аналогично поля периода и функции связаны через атрибут `name` HTML-форы.

### Блок 8. Шаблон и форма

**Фрагмент кода:**

```html
<form method="post" enctype="multipart/form-data">
<input type="file" name="image">
<input type="number" name="period" min="2" max="1000">
<select name="function"><option value="sin">sin</option><option value="cos">cos</option></select>
</form>
```

Multipart обязательен при передаче бинарного файла. Метод POST скрывает поля в теле запроса и не содержит их в URL. Jinja2 подставляет статический URL и данные результатов. Таблица с результатами позволяет разместить исходник и обработанное изображение рядом.

## 5. Вопросы преподавателя

1. **Почему выбран Flask?** Он достаточно прост для небольшого WSGI-приложения, имеет встроенный Jinja2 и не требует FastAPI-сервера и статики ASGI.
2. **Как работает маршрут `/`?** Декоратор связывает URL и функцию `index`; GET показывает форму, POST обрабатывает данные.
3. **Что такое multipart/form-data?** Это формат multipart-тела HTTP-запроса для одновременной передачи текстовых полей и бинарного файла.
4. **Почему проверяются и имя, и содержимое файла?** Расширение можно подменить, поэтому PIL читает реальную структуру и проверяет целостность.
5. **Почему ограничение размера важно?** Оно снижает риск исчерпания памяти или диска через крайне большие загрузки.
6. **Что означает EXIF-транспонирование?** Оно применяет ориентацию камеры к пиксельному массиву перед преобразованием.
7. **Почему изображение преобразуется в RGB?** Логика варианта 19 задается для каналов красного, зеленого и синего, поэтому альфа и палитра не нужны.
8. **Как определена периодическая матрица?** Для каждой пары координат вычисляется `2π(x/T+y/T)`.
9. **Что меняет cos по сравнению с sin?** Та же частота, но другое начальное значение фазы и другая сетка яркостей.
10. **Почему множитель нормируется в `[0,1]`?** Исходные каналы находятся в `[0,255]`, поэтому умножение должно сохранять допустимый диапазон.
11. **Как работает `np.clip`?** Выдает значения ниже 0 как 0 и выше 255 как 255.
12. **Зачем `.astype(np.uint8)`?** PIL получает массив байтов, где каждый канал представлен целым числом от 0 до 255.
13. **Что строит гистограмма?** Количество пикселей для каждого диапазона интенсивности трех каналов.
14. **Почему используется `.ravel()`?** Flatten-преобразование переводит двумерный канал в одномерную выборку для matplotlib.
15. **Почему графики передаются Base64?** Так Jinja2 вставляет готовые PNG прямо в HTML без хранения временных файлов на сервере.
16. **Как работает серверная проверка капчи?** Браузерный токен отправляется вместе с секретом на Google; сервер анализирует поле `success`.
17. **Почему ключи берутся из переменных окружения?** Секрет нельзя размещать в Git и в публичном JavaScript.
18. **Как Flask отображает ошибки?** Переменная `error` передается шаблону и выводится блоком с атрибутом role `alert`.
19. **Почему нейросеть не включена?** Вариант 19 не требует классификацию и детерминированная обработка требует меньше памяти и не усложняет PaaS-деплой.
20. **Чем заглушка отличается от реальной классификации?** Заглушка честно сообщает об отсутствии модели и не показывает искусственные имена классов.
21. **Как работает тестовый клиент Flask?** Он имитирует HTTP-запросы внутри процесса и проверяет POST и код ответа без реального браузера.
22. **Почему нужны три-плюс теста?** Тесты локально фиксируют поведение обработчика, графика, валидации и маршрута.
23. **Что делает CI?** При push устанавливает Python и зависимости, затем запускает pytest и не пускает сломанный код дальше в успешную сборку.
24. **Почему Render использует Gunicorn?** Это зрелый WSGI-сервер для production-запуска, а встроенный сервер Flask не предназначен для реальной нагрузки.
25. **Что означает `app:app` в Gunicorn?** Первая часть — модуль `app.py`, вторая — объект экземпляра Flask внутри этого модуля.
26. **Как запускаются переменные окружения?** В Render задаются вручную в настройках сервиса и читаются через `os.getenv`.
27. **Что будет без капчи в продакшене?** Форма работает, но защита отключена, потому что отсутствует секретный ключ.
28. **Какой формат гистограмм наиболее понятен?** Наложенные RGB-кривые позволяют сравнить концентрацию интенсивностей исходника и результата.
29. **Какая предельная проблема NumPy-операции?** Под размер исходника выделяется массив картинки и промежуточные массивы сетки и результата.
30. **Какие дальнейшие улучшения возможны?** JPEG-компрессия превью, асинхронная очередь обработки, ограничение размеров сторон, лимитер запросов и реальный classifier с ONNX.
